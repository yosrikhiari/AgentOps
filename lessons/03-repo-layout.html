The repo layout

In one sentence

One monorepo, one go.mod, five packages — each package is one of the tools.

Why it exists

A single module means one build, one test command, one binary. Interviewers like being able to run go test ./... and see the whole thing.

How it works in this project

AgentOps_Project_Plan/
├── main.go            # wires everything, parses flags, picks a mode
├── config.go          # env vars → Config struct
├── router/            # traffic cop: classify prompt, call Ollama, metrics, spans
├── tracker/           # durable 3-step workflow on Postgres rows
├── evals/             # corpus ingest, pgvector search, golden set, judge, drift
├── mcp/               # JSON-RPC over stdio, 5 tools
├── migrations/        # 0001_init.sql, 0002_drift.sql
├── corpus/            # 15 short markdown docs (the RAG source of truth)
├── scripts/           # clean_docs.py (chunker)
├── dashboard/grafana/ # router.json (5 panels)
├── load-tests/        # router.js (k6)
├── docs/              # VRAM.md
├── lessons/           # these pages
├── README.md · LICENSE (Apache-2.0) · PRIVACY.md
└── docker-compose.yml # Postgres + pgvector; --profile monitoring adds Prometheus + Grafana

Rule inside each package: handler → service → repo, and one JSON error shape everywhere: {"error":{"code","message","trace_id"}}.

The only external dependency is github.com/jackc/pgx/v5 (Postgres driver). Everything else is the Go standard library.

Try it yourself

Run go list ./... — you'll see exactly agentops, agentops/evals, agentops/mcp, agentops/router, agentops/tracker. Then cat go.mod — one direct dependency.

Interview questions

Q Why a monorepo and not one repo per tool?
A They share types (spans, the Ollama client), one DB schema and one binary. Splitting would add release coordination for zero benefit on a solo project. This is ADR-0001.
Q How do packages avoid depending on pgx?
A evals/ and tracker/ declare tiny interfaces (Execer, Queryer, Rows). main.go adapts pgx to them. So the packages are testable with in-memory fakes and never import the driver.
Q Where's the business logic vs the wiring?
A Logic in the packages; wiring (flags, DSN, pool, adapters) in main.go. main.go has no tests on purpose — it's glue.

Remember

  • 5 packages = 4 tools + wiring.
  • One dependency: pgx.
  • Packages talk to the DB through tiny interfaces.
