Part 2 · The router

Prometheus metrics, written by hand

In one sentence

The router counts requests, errors and tokens per model and keeps a latency histogram, then prints them in Prometheus text format at GET /metrics.

Why it exists

Prometheus is the standard for numbers-over-time. Writing the exposition format yourself (instead of importing the client library) teaches you what a counter and a histogram really are — and it's ~150 lines.

How it works in this project

# what /metrics prints
router_requests_total{model="qwen2.5:3b-instruct"} 42
router_errors_total{model="qwen2.5:3b-instruct"} 1
router_tokens_total{model="qwen2.5:3b-instruct"} 9130
router_latency_seconds_bucket{model="qwen2.5:3b-instruct",le="0.5"} 30   # requests that took <= 0.5s
router_latency_seconds_bucket{model="qwen2.5:3b-instruct",le="1"} 40
router_latency_seconds_bucket{model="qwen2.5:3b-instruct",le="+Inf"} 42
router_latency_seconds_sum{model="qwen2.5:3b-instruct"} 21.7
router_latency_seconds_count{model="qwen2.5:3b-instruct"} 42
eval_faithfulness 0.94                                                     # gauge, set by the eval suite

Three concepts:

  • Counter — only goes up (requests_total, tokens_total).
  • Gauge — can go up or down (eval_faithfulness).
  • Histogram — cumulative buckets: the le="1" bucket counts every request ≤ 1 s, including the ones already in le="0.5". The last bucket +Inf must equal _count.

Two real bugs lived here. (1) The le label was printed unquoted (le=0.05) — Prometheus would have rejected every scrape. (2) Observe already filled buckets cumulatively, and Expose summed them again, so one request showed le="120"} 11 and +Inf} 1. Both are now fixed and pinned by tests (TestMetricsRecordedPerRequest, TestHistogramBucketsAreCumulativeOnce).

Try it yourself

curl localhost:8080/metrics after a couple of chats. Check by eye: bucket values never decrease as le grows, and the +Inf value equals _count.

Interview questions

Q Why not use the official Prometheus Go client?
A Independence + learning. The exposition format is a documented text format; writing it forced me to understand cumulative buckets — and I found two bugs by understanding it.
Q How does the p99 panel work?
A Grafana runs histogram_quantile(0.99, rate(router_latency_seconds_bucket[5m])). It only works if buckets are correctly cumulative — which is exactly what the double-count bug broke.
Q Why not record latency on errors?
A So the histogram stays 'time to a real answer'. Errors get their own counter, router_errors_total, and their own Grafana panel.

Remember

  • Counter, gauge, histogram.
  • Histogram buckets are cumulative; +Inf == _count.
  • Label values must be quoted.
