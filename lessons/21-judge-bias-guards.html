LLM-as-judge: bias guards and prompt versioning

In one sentence

When a model grades another model, you must guard against its known biases and record exactly which judge and which prompt produced every score.

Why it exists

LLM judges prefer longer answers, agree with the first thing they read, and change behaviour between versions. If you don't control for that, a 'score drop' might just be a judge mood swing.

How it works in this project

Guards implemented in evals/judge.go:

  • Justification before verdict. The prompt forces 1–2 sentences of quoted evidence before the VERDICT line. Reasoning first makes the verdict less random.
  • Explicit 'ignore length and style' in the prompt, to counter verbosity bias.
  • Robust parsing. parseVerdict looks for REFUTED, NOT SUPPORTED or UNSUPPORTED first, then SUPPORTED. A deep-review found 'NOT SUPPORTED' used to parse as supported — because it contains the substring.
  • Provenance. Every run stores judge_model and the constant JudgePromptVersion = "faithfulness-v1". Change the prompt → bump the version.
  • Judge-change flag. The drift report says judge_changed: true if the last two runs used different judges, so you don't chase a ghost.
  • Temperature 0. The Groq judge always sent temperature: 0; the local Ollama judge sent nothing and sampled at the default. In the first full v1 run one pair scored 0.00 — asked again, the same judge said SUPPORTED. A coin-flip judge is not a metric. NewOllamaJudge now pins temperature 0 (TestOllamaJudgeSendsTemperatureZero).
// evals/judge.go
if strings.Contains(rest, "REFUTED") || strings.Contains(rest, "NOT SUPPORTED") || strings.Contains(rest, "UNSUPPORTED") {
    return false, just
}
if strings.Contains(rest, "SUPPORTED") { return true, just }

Two judges are wired: local qwen3:8b (free, everyday) and Groq's llama-3.1-8b-instant behind JUDGE_BACKEND=groq (free tier, 14,400 req/day) as a cross-check. Temperature 0 on Groq for repeatability.

Try it yourself

Run go test ./evals/ -v and read the verdict-parsing test names. The 'NOT SUPPORTED' case is the one that used to be wrong.

Interview questions

Q What biases does an LLM judge have?
A Verbosity (longer looks better), position (first option looks better in pairwise), self-preference, and drift across model versions. I counter with justification-first, explicit instructions, and logging judge + prompt version.
Q What was the parsing bug?
A 'VERDICT: NOT SUPPORTED' contains 'SUPPORTED', so a naive check returned true. Now the negative forms are checked first, with tests.
Q How do you know a judge verdict is stable?
A Run it twice. My first full run had one REFUTED that flipped to SUPPORTED on rerun — the local judge wasn't at temperature 0. Fixed and tested; determinism is a precondition for drift detection meaning anything.

Remember

  • Justification before verdict.
  • Check negative verdicts before positive ones.
  • Temperature 0 + log judge model + prompt version with every score.
