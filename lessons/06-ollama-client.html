Talking to a local LLM: the Ollama client

In one sentence

Ollama runs models on your GPU and exposes a plain HTTP API; the router calls POST /api/generate with the standard library.

Why it exists

No SDK, no LiteLLM. Calling Ollama directly is ~50 lines and shows you understand what an LLM API actually is: JSON in, JSON out, plus token counts.

How it works in this project

// router/ollama.go
type ollamaGenerateRequest struct {
    Model   string         `json:"model"`
    Prompt  string         `json:"prompt"`
    Stream  bool           `json:"stream"`             // false: one JSON reply, not a stream
    Options map[string]any `json:"options,omitempty"`  // {"num_predict": maxTokens}
}
type ollamaGenerateResponse struct {
    Response        string `json:"response"`
    PromptEvalCount int    `json:"prompt_eval_count"`  // input tokens
    EvalCount       int    `json:"eval_count"`         // output tokens
}

func (c *OllamaClient) Generate(model, prompt string, maxTokens int) (string, int, error) {
    // marshal → POST → check 200 → decode → return text + total tokens
    return out.Response, out.PromptEvalCount + out.EvalCount, nil
}

Two details that matter:

  • Timeout: 120s on the HTTP client — a 7B model on a laptop GPU can take a while; a missing timeout would hang forever if Ollama dies.
  • max_tokens maps to Ollama's num_predict. A deep-review found it was accepted and ignored before; now it's forwarded (test: TestMaxTokensForwarded).

Try it yourself

curl localhost:11434/api/generate -d '{"model":"qwen3:8b","prompt":"say hi","stream":false}'
That's exactly the request the router sends.

Interview questions

Q What's Ollama?
A A local model server. You ollama pull a model, it loads it onto the GPU and serves an HTTP API on :11434. One request at a time, which is fine for a solo box.
Q Why not stream?
A Streaming complicates metrics (when does latency end?) and traces. Non-streaming gives one reply with token counts — simpler and enough for the MVP.
Q How do you get token counts?
A Ollama returns prompt_eval_count and eval_count. I add them and feed the sum to the router_tokens_total counter.

Remember

  • Ollama = HTTP API on :11434.
  • Always set a client timeout.
  • Token counts come back in the response.
