Configuration from environment variables

In one sentence

All settings come from env vars with sensible defaults, read once at startup into a Config struct.

Why it exists

Twelve-factor rule: config lives in the environment, not in code. It makes the same binary work on your laptop, in Docker, and in Claude Desktop's MCP config — you just set different env vars.

How it works in this project

// config.go
type Config struct {
    OllamaURL    string   // OLLAMA_URL      default http://localhost:11434
    Addr         string   // ADDR            default :8080
    FastModel    string   // FAST_MODEL      default qwen2.5:3b-instruct
    QualityModel string   // QUALITY_MODEL   default qwen2.5:7b-instruct-q4_K_M
}

Other env vars are read where they're used in main.go:

  • POSTGRES_DSN — default postgres://agentops:agentops@localhost:5432/agentops
  • EVAL_THRESHOLD — default 0.7; below this, drift alerts
  • JUDGE_MODEL (default qwen3:8b) and JUDGE_BACKEND=groq + GROQ_API_KEY
  • EMBED_MODEL — default nomic-embed-text
  • DRAFT_MODEL — model used to draft golden pairs

Honest note: the plan used to say 'config.go fails loudly on missing env'. It doesn't — every value has a default, so the final if ollamaURL == "" check can never fire. That's fine for an MVP; the lesson is that a doc should match the code, and the plan now says 'defaults for everything'.

Try it yourself

FAST_MODEL=qwen3:8b go run . — the log line agentops router on :8080 fast=qwen3:8b ... proves the override worked.

Interview questions

Q Why env vars and not a YAML file?
A Fewer moving parts. Env vars work everywhere (shell, Docker, Claude Desktop's JSON config) and need no parser.
Q What happens with a bad EVAL_THRESHOLD like 'abc'?
A It silently falls back to 0.7. Acceptable for a solo tool; in production I'd fail fast and log the bad value.
Q Where is the DB connection string?
A POSTGRES_DSN, read in main.go, not in Config — because only DB modes need it and the router tests never touch a database.

Remember

  • Env vars → Config struct, read once.
  • Defaults match the plan's model pair.
  • Docs must match code — I found one that didn't.
