Retrieval precision and recall

In one sentence

Precision@k = of the k chunks we fetched, how many came from the right document. Recall@k = of the right documents, how many did we fetch.

Why it exists

Faithfulness tells you if the answer matches the context. Precision/recall tell you if the context itself was the right one. A perfect answer to the wrong passage still fails the user.

How it works in this project

// evals/scorer.go
func PrecisionRecall(retrieved []string, relevant []string, k int) (precision, recall float64) {
    retrieved = retrieved[:k]                    // top-k doc ids we fetched
    hits  := count of retrieved chunks whose doc is relevant     // a doc fetched twice counts twice
    found := set of relevant docs seen at least once             // a doc fetched twice counts once
    return hits / len(retrieved), len(found) / len(relevant)
}

The first version used hits for both. The full v1 run printed recall = 2.0 for one pair: 08-judges is the one doc that split into two chunks, both were retrieved, so 2 hits ÷ 1 relevant doc. Recall can't exceed 1 by definition — the average recall=1.031 in the log was the tell. Fixed with a set; TestRecallCountsUniqueDocs pins it.

Worked example, k=5, golden says the answer lives in 01-router: we fetch 5 chunks and 1 is from 01-router → precision 0.20, recall 1.00. That's what the live run printed, and it's honest: with one relevant doc per question, precision@5 can never exceed 0.20. The number isn't bad; the metric's ceiling is.

Try it yourself

Look at the p= and r= columns in a --score log. Recall is what matters with single-doc goldens: 1.00 means the right doc was in the top 5.

Interview questions

Q Precision was 0.20 — isn't that terrible?
A It's the ceiling. Each golden names one relevant doc; with k=5, the best possible precision is 1/5. Recall (did we find it?) is the informative number here.
Q How would you make precision meaningful?
A Either label more relevant docs per question, or measure at k=1, or compare chunk ids instead of doc ids. Each is a small change to PrecisionRecall.
Q How did you catch the recall bug?
A The suite average printed recall=1.031. A ratio bounded by 1 that averages above 1 means the formula is wrong somewhere — one pair had recall 2.0 because its doc's two chunks were both retrieved. Sanity-check every metric against its own bounds.

Remember

  • Precision = fetched that are right. Recall = right that were fetched (unique docs).
  • Single-doc goldens cap precision@5 at 0.20.
  • A bounded metric averaging out of bounds is a bug, not a result.
