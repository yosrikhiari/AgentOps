# Changelog

All notable changes. Dates are 2026.

## Unreleased

- **Model generation no longer waits on an eviction: small default context and keep_alive.** Trace 1434a15868f29f41 spent 95 s in an Ollama scheduler eviction before a 5.5 s load — the 3B fast model predicted 2.9 GiB at the server's 32768-token default context and only 1.1 GiB was free, so it evicted a neighbour on every turn. The gateway now injects `num_ctx: 4096` and `keep_alive: 5m` when a client omits them (a client sending `0` keeps "model default"), and the cockpit sends them explicitly; the predicted footprint drops to ~1.9 GiB and models stay resident between turns instead of reloading. `docs/API.md` documents the new defaults.

- **Cockpit now streams chat responses (SSE) instead of waiting for the full JSON.** Time-to-first-token drops from full `latency_s` (102 s in the bad case) to load time + first token (~6 s). Added a `chatStream` helper using `ReadableStream`/`TextDecoder` with `\n\n` event framing, progressive DOM updates of the assistant bubble, final-metadata extraction (usage, trace_id, model, backend, reason, tier, candidates), and abort handling. A Cancel button replaces abort-on-navigate. Backend adds `X-Accel-Buffering: no` and a 30 s SSE heartbeat (`: ping`) during long gaps so proxies/clients don't time out. Mid-stream failures mark the message failed with a click-to-retry. Also added a configurable external-app link (button + selector via localStorage) instead of hardcoded URLs, and documented cloud hosting behind Kong/nginx/Cloudflare (auth, rate limiting, TLS, timeouts). `docs/API.md` and `docs/OPS.md` updated.

- **The console works from a keyboard and a screen reader, and its five-second poll is silent.** A skip link is the first tab stop and lands on the content column, whose bare `#content` hash the router now ignores so skipping cannot tear the page down or restart its poll. A route change rewrites `document.title` (`Traces · Tower`), moves focus to the page heading and leaves exactly one `aria-current="page"` on the rail — but never on first paint or on a re-route to the same page, where it would steal the caret from the field being typed in. The `aria-live` on the content column, which re-read the whole page every time a poll replaced it, is gone; one narrow `#announcer` speaks filter result counts instead, and the toast is `aria-atomic` and flips to `assertive` for failures. Filter chips and both range switches state themselves with `aria-pressed`, the `×N` workflow group chip carries `aria-expanded` and a spoken name (its visible text is a count, not a control name), the workflow question input is labelled, and the nine rail icons are `aria-hidden` behind the text that names them. Each primitive is demonstrated and specified in `docs/tower-design-system.html#a11y`; 32 headless-browser assertions pass with zero console errors.

- **A conversation append is now one transaction, and the status columns are constrained at the database.** `AppendMessage` used to bump `conversations.updated_at` in one statement and insert the message in the next, with the title refresh as a third: a failure between the first two left a thread whose clock had moved but whose message was missing, so the cockpit showed a reply with no row. The three statements now run inside one transaction when a `Beginner` is wired (main.go supplies `pgAdapter`, which already satisfies pgx's `Beginner` through `pgDB`), and keep the old sequential behaviour when the store is built without a connection (tests, `memStore`). The transaction surface is deliberately tiny (`Tx`: `Exec`/`Commit`/`Rollback`) and mirrors `Execer`, so a transaction stands in for a plain execer without touching the call sites; `pgDB` gains `Begin` so `pgAdapter` can open one. Migration 0017 adds `CHECK` constraints to the columns the rest of the code assumes are clean: `eval_runs.status` in (running, complete, failed), `workflows.status` in (running, done, failed), `steps.status` in (pending, running, done, failed), `messages.role` in (user, assistant), and `messages` token counts non-negative. Each is added only when absent, so re-running `Migrate` on an upgraded schema is a no-op. The constraints are the last line of defence for direct psql or a future caller; the Go handlers already enforce them.

- **Contract fixes a client hits immediately:** the OpenAI ingress now refuses the parameters it cannot honour (`tools`, `tool_choice`, `n` other than 1, `logprobs: true`, `top_logprobs`) with `400 unsupported_field` naming every field, instead of returning 200 with plain prose that makes a tool-using client think its `tool_calls` ran; `n: 1` and `logprobs: false` are accepted because they ask for what the gateway already does. Every response now carries `X-Trace-ID`, including 404/405, console JSON and trace reads, where the id previously came back empty; a 404's header and body agree. The conversations reference now documents the real shape: a `{"conversations":[…]}` wrapper where `messages` is an integer count, not the array the doc implied.

- **Retention is a sweep, not a promise:** `spans` (30 d), `route_decisions` (90 d) and `audit_log` (365 d) are deleted at boot and every 24 h, each window set by `SPAN_KEEP` / `DECISION_KEEP` / `AUDIT_KEEP` and clamped to at least an hour so a typo cannot empty a table. Until now only GPU samples and idle conversations were purged: the three traffic tables grew forever while RULES and PRIVACY claimed a 30-day policy. `migrations/0016` adds `spans(name, started_at DESC)`, and the Requests scan is bounded to 24 hours, so the page stops reading every span ever written.

- **Workflow eval research + golden set (`docs/WORKFLOW-EVAL-RESEARCH.md`, `evals/golden/workflow-tasks.jsonl`).** Analyzed the "done but didn't do it" failure (false success / self-report leakage) against six papers (arxiv 2606.09863, 2610.29609, 2511.08242, 2607.28037, 2406.12045 τ-bench, 2611.14581). Proposed solution: outcome-based evaluation — replace agent self-report with a verifiable environment-state check (verifier predicate) per task. Added a 10-task golden set with verifiable outcomes (process running, file exists, HTTP 200, build passes, etc.) and `must_not` lists for self-report leakage. Implementation roadmap included.

- **Outcome-based workflow verification (docs/WORKFLOW-EVAL-RESEARCH.md).** A workflow is now 'done' only when its verifier passes, not when the agent claims success. Migration 0019 adds `verifier`, `verified`, `verifier_output`, `verified_at` to `workflows`. `runWorkflow` runs the verifier after the toy workflow completes and flips status to `failed` (with `verification_failed` audit) on failure. New `--workflow-verify <id>` CLI flag runs a verifier on demand. Console `#/workflows` gains a verified column (verified/unverified/pending pills) and an optional verifier command input. Console `POST /v1/workflows` accepts `verifier`. Golden set at `evals/golden/workflow-tasks.jsonl` (10 tasks with verifiable outcomes). Workflow type shown as a chip in the table.

- **The assistant answers questions about the gateway, and every request carries a server-built system prompt.** `why are you using this model`, `which models do you have` and a short follow-up (`why not another one`) are answered by the router itself — from the last model turn (model, tier, reason, latency) and the registered roster with tiers — with `"answered_by":"router"` and **no model call**: asking the component under discussion to describe itself from nothing is how a gateway invents its own routing. The trace is `route.decide → router.answer → router.respond`. Every other prompt gets one injected system message naming the roster (`name · tier · local/cloud`), the routing rule and this turn's model and reason, with "answer from this information and do not guess"; it is rebuilt per request, never stored (the client holds the thread, ADR-0010) and never spanned, and sensitivity is decided on what the client sent before it is added.

  Routing: `why` / `explain` / `compare` / `reason` now go to the quality tier even when short (reason `reasoning-prompt`), gateway questions get `gateway-question`, and `model` accepts the tier names the Cockpit picker sends (`fast` / `quality` / `cloud`, reason `explicit-tier`; an exact model name still wins). Responses (both wire shapes) gain `tier`, `candidates` and `answered_by`. The Cockpit footer now carries model · provider · route reason · tokens · `N spans · time` on every reply, each reply has a **why this model?** popover (tier, reason, every candidate considered) and **Retry with ▾**, and the composer has an Auto / fast / quality / cloud picker. Retries are a review action: they re-send the same user turn and are marked `not saved`, so comparing two answers never rewrites the stored thread.

- **A failed request no longer looks like a lost span, and the Cockpit stops counting a trace before it is written.** The failure path returned after `route.decide` and the erroring `model.generate`, so a failed chat had two spans and was indistinguishable from a dropped telemetry write; `router.respond` now carries the error too. Separately, the Cockpit fetched `/v1/traces/{id}` the moment a reply landed, while the spans were still in the async writer's queue — on a fast turn (a router answer replies in under a millisecond) the footer said "1 span" because only `route.decide` had been persisted. It now re-reads once after the writer settles, and shows `spans · …` instead of a number it does not have. `ListSpans` also orders spans parents-before-children: `started_at` is the writer thread's clock, coarse enough that two spans emitted back-to-back share it to the microsecond, and the old `ORDER BY started_at, span_id` then ordered a router's answer by a random id.

- **The release gate reads the run's real window, so "what was the card doing" finally answers:** the query selected `created_at` (the insert time, ~70 ms after `started_at`) and scanned it as the finish, so every window was empty and the GPU comparability check always printed "no samples (prober off) - comparability unknown". It now reads `COALESCE(finished_at, created_at)`, marks pre-0014 rows as having no recorded window, and the test asserts both the SQL and the 4-minute width. - **The scored path validates the golden file the same way `--freeze-golden` does:** `--score` (and the console's Run eval) parsed the JSONL itself, skipping duplicate-question, unknown-doc, empty-answer, no-claim and subordinate-clause checks. A duplicate silently overwrote the earlier pair on the primary key, and an unknown doc made recall meaningless. `evals.LoadGolden` is now the only reader for scoring; a duplicate file exits non-zero before a run row is created.

- **A pair with no scorable claim is unmeasured, not a zero:** it never reaches the judge, so averaging it in as faithfulness 0.0 depressed the suite score and could fail the gate. It is now counted (`no-claims`) and excluded from the mean, joining misses as a distinct fact rather than a score.

- **README corrected against the tree:** 244 tests and 19 policies (was 68/11), Go 1.26.11 (was 1.22+), the gated v3 baseline 0.914 with 8/72 unsolvable (was 0.972 and "70/70 faithful"), 15 migrations, 13 ADRs, 17 corpus docs, arm64 release binaries, and the nine real console pages.

- **A chat body is capped at 4 MiB, the server has real timeouts, and client `options` are bounded:** the audit found `r.Body` decoded with no `MaxBytesReader` on either ingress (so a 1 GB `messages` array was materialised in memory before a backend was chosen), only `ReadHeaderTimeout` configured (so a slow-trickled body held a connection forever), and `options`/`keep_alive` forwarded verbatim to Ollama (so `num_ctx: 2000000` or `keep_alive: "999h"` could take the card away from every other user). Now: `413 request_too_large` past 4 MiB; `ReadTimeout` 60s, `WriteTimeout` = `REQUEST_TIMEOUT` + 30s, `IdleTimeout` 120s, with the SSE rail opting out of the write deadline so a live view is not cut at the chat budget; `num_ctx` ≤ 32768, `num_gpu` ≤ 99, `num_predict` ≤ 8192, `num_thread` ≤ 256, `repeat_last_n` ≤ 4096, `keep_alive` between 0 and 1h, anything else `400 option_out_of_range` naming the option. Unknown option keys still pass through.

- **`POST /mcp` uses the chat gate and charges what a tool spends:** it previously checked only that the key existed, so a 1-rpm key could call `route_test_request` — a real model call — in a loop. It now reuses `Router.Authenticate` (valid, enabled, budget, RPM) and adds the tokens the tool reported to the key's counter. Discovery and read-only tools report zero and are never charged.

- **The console is a local surface and the default bind is loopback:** the audit found the key check guarded `/v1/chat/*` only, while the console — which returns stored prompts verbatim (`GET /v1/conversations/{id}/messages`), starts GPU-bound eval runs and deletes threads — was mounted outside it on `:8080`, listening on every interface with auth off. `ADDR` now defaults to `127.0.0.1:8080`; console routes refuse non-loopback peers with `403 console_local_only` unless `CONSOLE_REMOTE=true`; the compose file widens the container bind but publishes `127.0.0.1:8080` so the only reachable client is the host. Same change adds `Content-Security-Policy`, `X-Frame-Options: DENY`, `nosniff` and `Referrer-Policy` to every response, and uses the standard library's `http.CrossOriginProtection` (Go 1.25+) so a malicious page cannot POST `/v1/evals/run` or DELETE a conversation through an operator's browser. Non-browser clients — curl, SDKs, agents — send no fetch metadata and are unaffected.

- **The project builds with Go 1.26.11, not 1.26.7 — CI found what a local scan hid:** `govulncheck` in Actions reported **13 vulnerabilities from the Go standard library** because `go.mod` pinned the patch and `setup-go` installs exactly that, while the local scan silently ran under a newer toolchain (the scanner itself declares `go 1.26.11`, so `GOTOOLCHAIN=auto` upgraded the run and the stdlib under it). The `go` directive is now `1.26.11`, so dev builds, CI and the release binaries all use the patched standard library; the built binary reports `go1.26.11` in `go version -m`, and the scan is clean.

- **Both Docker base images are pinned by digest as well as tag** (`golang:1.27-alpine@sha256:70bd…`, `distroless/static-debian12:nonroot@sha256:afa5…`): a tag is mutable, and the release story is that a compromised dependency cannot silently change the artefact. Dependabot's docker ecosystem keeps both fresh; the image was rebuilt and `docker run tower:ci --version` checked locally.

- **CodeQL joins the gate, as its own workflow:** `security-extended` queries on Go run weekly and on every change to `main`/PRs, uploading SARIF as a security alert rather than a red build on an unrelated PR — semantic bug classes (injection, path traversal, unsafe deserialisation) that `govulncheck` cannot see because no CVE exists yet.

- **CI now proves the migrations, the image and the release manifest, and the Go graph is clean:** `govulncheck` (pinned to v1.10.0, not `@latest`) found `GO-2026-6629` reachable through `pgx.Connect` in `golang.org/x/text@v0.39.0`; the indirect dependency is now v0.41.0 and the scan is clean. New `schema` job applies all 15 migrations to an empty `pgvector` service and asserts a second run applies zero — the policy test only checked numbering, never the SQL. - **The judge explains itself in three labels, and a run records which prompt produced it:** a claim is now `entailed`, `contradicted` or `baseless` (`faithfulness-v2`), not just supported/refuted, because "the context says the opposite" and "the context does not mention it" are different failures with different fixes — and collapsing them is why a 0.00 score could not be explained. - **Heat is recorded as a consequence, not only a reading (`0012_gpu_thermal.sql`):** the prober now reads `clocks_event_reasons.active` from `nvidia-smi` and stores `throttled` on every `gpu_samples` row when the driver has cut clocks for heat (bits `0x20` SW / `0x40` HW thermal slowdown). ## v1.0.0 - 2026-09-15

The MVP becomes a product: an installable gateway with a console.

### Track A — ops foundation
- `Dockerfile` (multi-stage, distroless nonroot, 21.7 MB) and a compose `app` profile that runs the router against the host's Ollama.
- GitHub Actions: gofmt · vet · `test -race` · build · docker build on every push; release job on `v*` tags builds linux/windows/darwin binaries + `SHA256SUMS`.
- `schema_migrations` tracking: `--migrate` applies each `migrations/*.sql` once and reports the count.
- Dependabot for Go modules, Docker base images and Actions. `--version` flag stamped at release.

### Track B — gateway hardening
- **OpenAI-compatible** `POST /v1/chat/completions`: `messages[]` in, `chat.completion` out, with `text/reason/backend/trace_id/fallback` extensions. The MVP `{prompt}` body still works.
- **Streaming** (`stream: true`) as SSE in the OpenAI chunk shape; usage in the final chunk.
- **Backends**: `Backend` interface; Ollama moved to `/api/chat` with NDJSON streaming; `OpenAIBackend` for Groq or any OpenAI-style API; 15 s health prober → `router_backend_up{backend}`; `GET /v1/models`.
- **Virtual API keys** (`0003_api_keys.sql`, `--create-key NAME --key-rpm N --key-budget T`): Bearer auth, per-key requests-per-minute, lifetime token budget, 401/403/429 in the one error shape, per-key counters.
- **Fail-closed rule**: sensitive requests (header, body flag, keyword) never get a cloud candidate; explicit cloud model → `403 sensitive_cloud_blocked`.
- Graceful shutdown (drain in-flight chats, flush spans), `REQUEST_TIMEOUT` → 504, `X-Trace-ID` on every response, `X-Request-ID` echo.

### Track C — Tower console
- Web UI served from the binary at `/` (embedded HTML/CSS/JS, no framework, no build step): overview (KPIs, routing traffic, backend health, recent requests), trace inspector, evals & drift (score history, worst cases, *Run eval suite*), workflows (start/resume).
- Console endpoints: `/v1/overview`, `/v1/requests`, `/v1/evals/{runs,status,run}`, `/v1/workflows` (+ `/{id}/resume`).
- Hardening: abortable fetches, one retry on 5xx, inline error + Retry on store failure, in-place polling.

### Fixes and learnings recorded along the way
- Prometheus histogram was double-cumulated (p99 would have been wrong). Fixed + test.
- Recall could exceed 1 when a doc's two chunks were both retrieved. Fixed + test.
- Local judge sampled at default temperature; pinned to 0. Fixed + test.
- Golden answers must be standalone main-clause sentences (one-word, list, and "Because…" answers score 0). `--freeze-golden` now rejects them.
- Eval run budget is `EVAL_TIMEOUT` (default 90 min); evals and live traffic contend for the 8 GB GPU (`docs/VRAM.md`).
