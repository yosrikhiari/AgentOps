How to tell this story in an interview

In one sentence

Pitch it as: 'I built a focused, from-scratch version of the AgentOps pattern — router, durable tracker, evals, traces — in Go, informed by how TensorZero, Bifrost, Temporal and Langfuse solve the same problems.'

Why it exists

Claiming novelty invites 'isn't that just TensorZero?'. Claiming understanding — you studied the real tools and rebuilt the core with your own decisions and tests — is a stronger, more credible answer.

How it works in this project

A 90-second version:

  • Problem. Running LLMs in a product raises four ops questions: which model, what if it crashes mid-task, is it still truthful, what happened to this request.
  • What I built. One Go binary: a heuristic router over two local Ollama models with hand-written Prometheus metrics; a Postgres-native durable tracker proven by a kill-resume test; a claim-level faithfulness scorer with bias guards, retry/backoff and drift alerts; OTel-shaped traces; and an MCP server so Claude can query all of it.
  • Decisions I can defend. pgvector over a separate vector DB (ADR-0004). Row-status durability over DBOS (ADR-0003). Scheduler as a flag (ADR-0006). Per-question eval rows for worst-case reporting (ADR-0005). Heuristic router first, classifier later.
  • What went wrong. A deep-review found 15 defects after tests were green — the Prometheus label bug would have blanked the dashboard. I fixed each with a test that fails on the old code.
  • What's next. Pull the Qwen2.5 pair, run k6 + Grafana, record the MCP demo. Then corpus v2 (docs rewritten to match the shipped code) and shadow-test auto-promotion of the cheaper model.

Numbers to have ready: 5 packages, 1 dependency, 38 tests, 5 MCP tools, 5 Grafana panels, 7 tables, 15 docs → 16 chunks, 32 golden pairs (frozen v1), 3 spans per chat, faithfulness 1.00 vs 0.00 on good vs corrupted answers, 0.969 on the full frozen set.

Try it yourself

Say the 90-second version out loud, once, with the numbers. Then open any lesson in this folder and answer its three Q&As without looking.

Interview questions

Q Isn't this just a toy?
A It's small on purpose — every piece is real: real Prometheus format Grafana reads, real MCP a Claude client speaks, real durability against a real kill, real judge calls with real retry policy. Small and finished was the goal.
Q What would you do differently?
A Write the corpus docs after the code, not before — several describe the planned design (DBOS, 3 MCP tools) rather than what shipped, which is fine for a RAG target but confusing for a reader. And add a schema_migrations table before the first ALTER.
Q Why should we believe your tests?
A Because I bind-checked them: revert the fix, the test fails. And because three of the six checkboxes were closed by live runs recorded in the plan, not by 'code exists'.

Remember

  • Pitch understanding, not novelty.
  • Problem → built → decisions → what broke → next.
  • Have the numbers ready.
