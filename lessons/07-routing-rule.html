The routing rule (the 'traffic cop')

In one sentence

A prompt goes to the fast 3B model unless it is longer than 200 characters or contains a 'complex' keyword — then it goes to the quality 7B model.

Why it exists

The 7B model is slower and eats more VRAM. Most prompts ('hi', 'what time is it') don't need it. A rule you can explain in one sentence is a legitimate routing decision — and it beats a classifier you can't demo.

How it works in this project

// router/router.go
const (
    FastReason    = "short-simple-prompt"
    QualityReason = "long-or-complex-prompt"
)

var complexKeywords = []string{
    "analyze", "compare", "prove", "contract", "summarize",
    "analyse", "comparer", "résume", "contrat", "facture",   // French too
}

func Classify(prompt string) (tier string, reason string) {
    p := strings.TrimSpace(prompt)
    if len(p) > 200 {
        return "quality", QualityReason
    }
    for _, kw := range complexKeywords {
        if strings.Contains(strings.ToLower(p), kw) {
            return "quality", QualityReason
        }
    }
    return "fast", FastReason
}

The reason string is returned to the caller and stored on the trace, so every request can answer 'why did this go where it went?'. Three tests pin it: short→fast, 201 chars→quality, keyword→quality.

Try it yourself

curl -s localhost:8080/v1/chat/completions -d '{"prompt":"hi"}'
# → {"text":"...","model":"qwen2.5:3b-instruct","reason":"short-simple-prompt","trace_id":"..."}
curl -s localhost:8080/v1/chat/completions -d '{"prompt":"compare these two contracts ..."}'
# → "reason":"long-or-complex-prompt"

Interview questions

Q Isn't a length check too simple?
A It's a heuristic, and I say so. It's deterministic, testable, explainable, and costs 0 ms. The backlog has a learned classifier and shadow-testing as a v2 — after the MVP works.
Q Why the French keywords?
A The target users write in French (Tunisia). 'facture' (invoice) or 'contrat' signal a document task that deserves the quality model.
Q How would you improve it?
A Log (prompt features, model, latency, eval score) per request, then train a tiny classifier or use shadow-testing: run both models, score both, promote the cheaper one when it's statistically as good.

Remember

  • Rule: >200 chars or keyword → quality, else fast.
  • Reason string travels with every response and span.
  • Simple + explainable beats clever + undemoable.
