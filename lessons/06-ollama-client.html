Talking to a local LLM: the Ollama backend

In one sentence

Ollama runs models on your GPU and exposes a plain HTTP API; the gateway calls POST /api/chat with the standard library — one JSON reply, or a newline-delimited stream.

Why it exists

No SDK, no LiteLLM. Calling Ollama directly is ~100 lines and shows you understand what an LLM API actually is: messages in, text and token counts out, and a stream that ends with a final object carrying the counts.

How it works in this project

// router/ollama.go — one of the Backend implementations (see lesson 31)
type ollamaChatRequest struct {
    Model    string         `json:"model"`
    Messages []Message      `json:"messages"`
    Stream   bool           `json:"stream"`
    Options  map[string]any `json:"options,omitempty"`   // {"num_predict": maxTokens}
}
type ollamaChatResponse struct {
    Message         Message `json:"message"`            // .content is the text (or a delta)
    Done            bool    `json:"done"`               // last line of a stream
    PromptEvalCount int     `json:"prompt_eval_count"`  // input tokens
    EvalCount       int     `json:"eval_count"`         // output tokens
}

func (c *OllamaClient) Generate(ctx, model, msgs, maxTokens) (string, Usage, error)   // stream:false
func (c *OllamaClient) Stream(ctx, model, msgs, maxTokens, emit func(string)) (Usage, error)   // stream:true, NDJSON
func (c *OllamaClient) Health(ctx) error                                              // GET /api/tags

Three details that matter:

  • A 300 s client timeout and the request context — a 7B model on a laptop GPU can take a while; a missing timeout would hang forever if Ollama dies, and a cancelled client must stop the model call.
  • max_tokens maps to Ollama's num_predict. A deep-review found it was accepted and ignored before; now it's forwarded (test: TestMaxTokensForwarded).
  • The stream's final line (done:true) carries the token counts, so a streamed request is metered exactly like a non-streamed one (TestOllamaChatAndStream replays real NDJSON).

Try it yourself

curl localhost:11434/api/chat -d '{"model":"qwen2.5:3b-instruct","messages":[{"role":"user","content":"say hi"}],"stream":false}'
That's exactly the request the gateway sends. Drop stream:false to see the NDJSON lines.

Interview questions

Q What's Ollama?
A A local model server. You ollama pull a model, it loads it onto the GPU and serves an HTTP API on :11434. One request at a time, which is fine for a solo box.
Q Why /api/chat instead of /api/generate?
A The MVP used /api/generate with one prompt string. The v1.0 gateway speaks the OpenAI messages[] shape, and /api/chat takes messages natively — no prompt-templating on my side. The evals package still uses /api/generate for the judge, which really is one prompt.
Q How do you get token counts?
A Ollama returns prompt_eval_count and eval_count. I add them and feed the sum to the router_tokens_total counter — for streams, from the final done:true line.

Remember

  • Ollama = HTTP API on :11434; /api/chat takes messages.
  • Timeout + context on every call.
  • Token counts come back in the reply — last line for streams.
