How to read this

Each example: what the console does today (with the line that does it), the proposal, a working demo in Tower's own CSS, and an impact / effort call.

The console already does the hard things right — every page has loading, empty and error states, ids link everywhere, nothing is stored that shouldn't be. What is left is the layer that separates a tool people use from one they trust: keyboard reach, contrast, motion respect, wayfinding, and making live data feel live without being noisy. Three of the twenty are accessibility defects rather than enhancements (01, 02, 03) and should go first. Nine are quick wins (a CSS block or under 40 lines of JS). The rest are half-day pieces that change how the Traces and Evals pages feel.

01

Visible focus rings and keyboard reach

a11y defectcss only
Today

tower.css: .tower-input:focus{ outline:none; border-color:amber } — the input gets an amber border, but buttons, nav items, chip filters, trace list cards and table links have no focus style at all: the browser default outline is the only cue and it is invisible on this dark ground. A keyboard user cannot see where they are. Trace list items are div onclick, so they are not reachable by Tab either.

Proposal

One rule, :focus-visible only (mouse clicks stay clean): 2 px amber outline, 2 px offset. Make list cards <button> or tabindex="0" + Enter/Space handlers. Add j/k to move the selection in the traces list and Enter to open.

:is(button,a,input,[tabindex]):focus-visible{ outline:2px solid var(--tower-amber); outline-offset:2px; } .tower-trace-item{ /* becomes a button */ } .tower-trace-list:focus-within .tower-trace-item.selected{ outline:… }
Tab through this — then try j / k in the list

02

A contrast-safe ink-faint

a11y defect1 token
Today

--tower-ink-faint:#635C63 is used for text: every table header (11 px!), nav group labels, the version in the sidebar, timestamps in the trace list, key names in attributes, and chart axis labels. On surface #201D22 it measures – — WCAG AA needs 4.5:1 for text this size, 3:1 for large text. It fails both.

Proposal

Split the token by intent. Keep the current value as --tower-ink-ghost for non-text use (trace dots, dividers, the fast-tier bar colour where a legend explains it). Introduce --tower-ink-faint:#8B838B for text — still clearly quieter than muted, but –. Use the picker to try your own.

--tower-ink-ghost:#635C63; /* decorative only */ --tower-ink-faint:#8B838B; /* smallest text: th, labels, hints */

03

Respect reduced motion; make a light theme possible

highcss only
Today

The live dot pulses and skeletons shimmer forever, with no prefers-reduced-motion guard. The palette is dark-only, but every colour is already a token, so a light theme is a second :root block — the console runs on office monitors in daylight and in Grafana's light mode next door.

Proposal

Add the motion guard (and stop the toast timer bar from example 16 under it). Ship a light token set on [data-theme="light"], pick it from prefers-color-scheme with a manual override in the sidebar footer, persisted in localStorage. Amber gets darker in light (#B96F05) so it still passes on white.

@media (prefers-reduced-motion: reduce){ .tower-pulse-dot, .tower-skeleton{ animation:none; } } :root[data-theme="light"]{ --tower-ground:#F6F3EE; --tower-surface:#fff; … }

04

Command palette

high~120 lines
Today

Reaching a trace means: click Traces, click the input, paste, Enter. Running the eval suite means Evals → button. Every operator action lives on exactly one page and there is no way to jump. The trace-id input on the Traces page is the only "search" in the product.

Proposal

ctrl+K opens a palette with three groups: Go to (pages, Metrics, Models), Actions (Run eval suite, Start workflow, Copy curl), and Recent traces (the same list the Traces page loads). Anything that looks like a trace or workflow id opens it directly. Arrow keys move, Enter runs, Esc closes. It replaces nothing — it is a second door to everything.

mediumquick win
Today

Deep links work (#/traces/<id>) and the sub line says "Showing the latest trace — pick another on the left". But the strip title is just "Traces"; from a workflow's trace there is no way back to the workflow row; "Copy id" copies the id, not a URL a colleague can open.

06

Filters live in the URL and show their counts

mediumquick win
Today

app.js pageTraces: let filter = 'all' — the filter is a local variable. Reload, or open a trace from the Overview, and it resets to All. The chips do not say how many items they hide, so "Errors" being empty looks like a bug rather than good news.

Proposal

Encode it: #/traces/<id>?f=error. Read on route, write on toggle with history.replaceState. Each chip renders its count; a zero-count chip is disabled rather than hidden so the operator learns the vocabulary.

07

Live tail: diff the rows, flash the new ones, pause on hover

high~60 lines
Today

pageOverview(…, polling=true) re-fetches every 5 s and calls content.replaceChildren(…) — the whole page is rebuilt. Hover states vanish, an expanded row would collapse, scroll position inside the table resets, and a new request is indistinguishable from an old one. The only guard is "don't replace while typing".

Proposal

Key rows by trace_id. On poll, prepend only unseen rows with a 1.6 s amber-dim fade (tower-row-in) and drop rows past the limit. Show a small live indicator that turns amber and reads "paused" while the pointer is over the table, and resumes on leave. Metric cards update in place (see 08).

A request arrives every ~2 s · hover the table to pause

08

Sparklines and count-up in metric cards

medium~50 lines + api
Today

A metric card is label · value · delta text. "184 requests / last hour, 12 in the last minute" is a number without a shape: was it a burst or steady? /v1/overview already computes hourly aggregates; it does not return the per-minute series.

Proposal

Return traffic.series_1h: [60 ints] and latency.series_1h. Render a 28 px SVG polyline under the value in ink-faint with the last point in amber. When a value changes between polls, tween the number (400 ms, tabular-nums keeps the width stable). On Evals, the faithfulness card gets the last 10 run scores as its sparkline.

09

Relative time everywhere, absolute on hover, ticking

mediumquick win
Today

Three formats coexist: fmt.time (11:42:07) in the requests table, fmt.date (full locale string) in runs and workflows, fmt.ago (3 min ago) only in the trace list. "11:42:07" needs the operator to know what time it is now; "15/09/2026, 11:42:07" is 20 characters for the same fact.

Proposal

One helper when(iso) returning <time datetime title="absolute">3 min ago</time>. A single 30 s interval refreshes every time.tower-rel on the page. Past 24 h it switches to date + time. The absolute value stays one hover away and stays in the DOM for copy.

10

Skeletons shaped like what is coming

mediumquick win
Today

skeleton(rows) renders N full-width 14 px bars. Every page shows the same six bars, then snaps into a completely different layout — the metric row, two panels, a table. The eye has to re-find everything.

Proposal

Three shaped skeletons that mirror the real components: skelMetrics(n), skelTable(rows, cols), skelPanel(title). The Overview skeleton is metric row + grid-2 + table, so the layout is stable before the data lands and the reveal is a fill, not a jump.

11

Chart tooltips that are actually tooltips

high~40 lines
Today

Both charts use SVG <title> for hover: a native tooltip that appears after ~1 s, in the OS font, unstyled, and disappears the moment the pointer moves. On a 30-bar chart the operator sweeps across and sees nothing.

Proposal

One absolutely positioned .tower-tip per chart, moved on pointermove, showing time · model · latency · reason with a key/value layout. The hovered bar brightens; a thin crosshair line marks it. Clicking still opens the trace. Same component serves the score chart.

12

Latency bands over time instead of 30 bars

highapi + chart
Today

"Routing traffic — last 30 requests" is a per-request bar chart. At 184 requests an hour it shows the last ten minutes; under load it shows the last thirty seconds. It answers "what just happened", not "is latency drifting".

Proposal

Keep the bars as the "last 30" strip, and add a time-bucketed area: p50 as a line, p50–p95 as a band, p99 as dots, errors as red ticks on the baseline, 1-min buckets over the last hour (60 points from the API). Hover gives the bucket's counts. This is the chart that makes the "p50 312 ms" strip number trustworthy.

13

Waterfall ruler, hover sync, critical path

high~70 lines
Today

The waterfall has no time axis; a bar at 40 % width means nothing without reading the duration column. Waterfall rows and the span tree below are two lists of the same spans with no link between them — the eye does the join. Nothing tells the operator which span made the request slow.

Proposal

A ruler row with 4–5 ticks in ms. Hovering a waterfall row or a span-tree step highlights both (same data-span attribute). Compute the critical path — the chain of longest children from the root — and outline those bars in amber; the duration column shows its share of the total in ink-faint.

14

A typed attribute viewer with per-key copy

medium~60 lines
Today

tower-kv renders every attribute as a grey string: JSON.stringify(v) for objects, String(v) otherwise. fallback_from shows as ["groq/llama…"], booleans and numbers look like words, a long error message wraps for six lines, and copying one value means selecting text by hand.

Proposal

Colour by type (string green, number amber, boolean red, null faint), render arrays as chips, truncate strings over 120 chars with a "… more" toggle, and show a copy affordance on row hover. Keys are sorted with the important ones (error, model, latency_s) pinned first.

Hover a row for copy · click "… more"
15

Search within a trace, errors only, expand all

mediumquick win
Today

A workflow trace has a dozen spans; each step's attributes open one click at a time (detail.classList.toggle('open')). Finding the span with the error means opening them all. There is no filter inside a trace.

Proposal

A small toolbar above the span tree: a text filter that matches span names and attribute values, an errors only chip, and Expand all / Collapse all. Failed spans open by default (they already get the amber dot). With 15 spans this is a nicety; with 60 it is the feature.

16

A toast queue with actions and a visible timer

medium~50 lines
Today

toast(msg, isErr) writes into one fixed element and resets a 4 s timer. Start a workflow and copy an id within four seconds and the first message is gone. "Workflow wf_71ab started" is a dead end — the operator wants to open it.

Proposal

A stack (max 3, oldest drops), each toast with an optional action (View, Undo, Retry), a 2 px timer bar so the dismissal is predictable, pause on hover, and ok / err variants by border colour. Errors stay until dismissed.

17

Loading and confirm-in-place button states

mediumquick win
Today

runBtn.textContent = 'Starting…'; resume.disabled = true — the button dims and the label changes, and its width jumps. Resume fires on a single click on a row action; a stray click re-runs a workflow. There is no destructive action yet, but "Cancel eval run" (18) will be one.

Proposal

A busy(btn, label) helper: swaps in a spinner, keeps min-width from the resting size, restores on settle. A confirm class for two-click actions: the first click turns the button red-dim with "Sure?" for 3 s; the second executes. Esc or blur cancels.

18

Eval progress with ETA and cancel

highapi + ui
Today

A golden v3 run is 72 pairs through a local judge — up to 90 minutes (EVAL_TIMEOUT). The console shows "Running…", a disabled button, and polls every 5 s. The operator cannot tell if it is at pair 3 or pair 70, and cannot stop it (GPU contention with live traffic is documented).

Proposal

/v1/evals/status gains done, total, started_at, current_question; the runner updates it per pair. The Suite-status card becomes a progress bar with "34 / 72 · ~4 min left" (ETA from mean pair time) and the question in flight, plus a confirm-in-place Cancel that cancels the run's context. Partial results are kept and marked.

19

Sortable, sticky-header, density-switchable tables

medium~80 lines
Today

Every table is "newest first", full stop. Finding the slowest request in the last 30, or the worst run of 50, means scanning. Headers scroll away in the trace list and the runs table. Rows are 8 px padded — fine on a laptop, generous on a 27" where an operator wants 40 rows on screen.

Proposal

A table(cols, rows, {sortable, sticky}) helper: click a header to sort (mono columns sort numerically), arrow shows direction, sticky thead inside a scroll box. A density toggle in the sidebar footer flips a .compact class on body (4 px rows, 12 px type), remembered in localStorage.

Glossary tooltips and a shortcut sheet

mediumquick win
Today

"Faithfulness (v3)", "P@5", "R@5", "drift", "judge changed — not corpus drift": the vocabulary is exact and the console assumes the reader wrote the evaluator. A new operator has to open docs/API.md to learn that faithfulness is claim-level support by retrieved chunks.

Proposal

A .tower-term[data-def] span on every metric label with a one-sentence definition on hover / focus, sourced from a single GLOSSARY map so the wording is consistent with the docs. And once 01 and 04 exist, ? opens a sheet listing the shortcuts — a feature nobody discovers otherwise.
