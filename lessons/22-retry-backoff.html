Retry with backoff — and when NOT to retry

In one sentence

Judge calls retry with exponential backoff and jitter, honour Retry-After on 429, and never retry a 4xx that is the caller's fault.

Why it exists

Real practitioners report that parallel judge calls hit timeouts and flaky 500s. Retrying blindly is worse: a bad API key would be retried four times with growing waits, hiding the real error.

How it works in this project

// evals/judge.go
func WithRetry(ctx, attempts int, base time.Duration, fn func() error) error {
    for i := 0; i < attempts; i++ {
        if err = fn(); err == nil { return nil }
        if Permanent(err) { return err }                 // 4xx except 429 → give up now
        wait := base * (1 << i)                          // 1s, 2s, 4s, ...
        if rateLimited { wait *= 2; if rl.After > wait { wait = rl.After } }   // honour Retry-After
        wait += rand(base)                               // jitter: don't stampede
        select { case <-ctx.Done(): return ctx.Err(); case <-time.After(wait): }
    }
    return err
}

type StatusError struct{ Backend string; Code int }
func Permanent(err error) bool {                         // 400–499 minus 429
    var se *StatusError
    return errors.As(err, &se) && se.Code >= 400 && se.Code < 500 && se.Code != 429
}

TestWithRetryNeverRetries4xx covers 401 (stop), 503 (retry) and 429 (retry, longer wait). The context check means a cancelled run stops waiting immediately.

Try it yourself

go test ./evals/ -run Retry -v. Read the test names — they are the policy.

Interview questions

Q Why never retry 4xx?
A 4xx means my request is wrong: bad key, bad model name, oversized prompt. Sending it again can't help. 429 is the exception — it means 'slow down', so we wait and retry.
Q What's jitter for?
A If 30 workers all fail at once and all retry after exactly 2 s, they hit the server together again. Random extra wait spreads them out.
Q How do you pass typed errors through Go?
A A StatusError struct with the code, and errors.As to detect it through wrapping. That's how Permanent() decides.

Remember

  • Exponential backoff + jitter.
  • 429 → wait (honour Retry-After). Other 4xx → stop.
  • Respect context cancellation.
