What AgentOps is, in one breath

In one sentence

AgentOps is four small tools that make running AI models safer: a traffic cop, a task tracker, a fact-checker, and a dashboard.

Why it exists

When you put an AI model behind a product, four boring questions show up fast:

  • Which model should answer this request? (cheap and fast, or slow and smart?) → the router.
  • What if the program crashes halfway through a 3-step AI task? → the tracker.
  • Is the AI still telling the truth, or did it quietly get worse? → the evals (fact-checker).
  • What actually happened to request #4123? → metrics + traces + MCP (the dashboard).

Big companies use TensorZero, Langfuse, Temporal and LiteLLM for these. This project builds a small, honest version of the same pattern in one Go binary, so you can explain every line.

How it works in this project

Everything lives in one Go module named agentops. One binary, several modes:

go run .                    # HTTP router on :8080  (traffic cop)
go run . --mcp              # same server, but speaks MCP over stdin/stdout (dashboard for AI clients)
go run . --run-tracker      # runs the 3-step toy agent through the durable tracker
go run . --score            # runs the fact-checker over the golden question set
go run . --drift            # prints "did the score drop since last time?"

The four tools share one Postgres database (with the pgvector extension) and one local model server (Ollama).

Try it yourself

cd into the project and run go test ./... -count=1. You should see 4 packages pass: evals, mcp, router, tracker. That is the whole system, tested.

Interview questions

Q What does your project do?
A It's an AI operations toolkit: it routes chat requests to the right local model, keeps multi-step AI tasks alive across crashes, scores whether the AI's answers are faithful to source documents, and exposes all of that as metrics, traces and MCP tools.
Q Is it a product?
A No — it's a focused, from-scratch version of the pattern TensorZero / Langfuse / Temporal cover, built to prove I can do ML-systems work end to end.
Q What language and why?
A Go. Single static binary, great HTTP stdlib, goroutines for the async bits, and it forced me to write the Prometheus, MCP and durable-step logic myself instead of importing frameworks.

Remember

  • Four tools: router, tracker, evals, observability.
  • One Go binary, one Postgres, one Ollama.
  • Small and finished beats big and half-done.
