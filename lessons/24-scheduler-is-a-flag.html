The scheduler is a flag, not a service

In one sentence

--schedule-evals 24h runs the exact same scoring function in a loop, forever, and logs loudly if one tick fails.

Why it exists

A separate scheduler service means another process, another config, another thing to deploy. A loop in the existing binary can be run by cron, systemd, Docker or a terminal. ADR-0006.

How it works in this project

// main.go
func runScheduler(dsn, ollamaURL, goldenPath, goldenVersion, every string) {
    d, err := time.ParseDuration(every)              // "24h", "30m"
    if err != nil || d <= 0 { log.Fatalf(...) }
    for {
        if err := scoreOnce(dsn, ollamaURL, goldenPath, goldenVersion); err != nil {
            log.Printf("scheduled eval failed: %v", err)   // loud, but the loop survives
        }
        log.Printf("next scheduled eval in %s", d)
        time.Sleep(d)
    }
}

Two properties worth naming: it shares scoreOnce with --score and with the console's Run eval suite button (single-flight: a second click gets 409), so there is one code path to test; and the golden file is re-read every tick, so freezing a new version is picked up without a restart. A run is bounded by EVAL_TIMEOUT (default 90 min) — needed because an eval and live traffic contend for the 8 GB GPU (see docs/VRAM.md). The HTTP server loads the eval_faithfulness gauge from the latest stored run at startup.

Try it yourself

go run . --schedule-evals 30m --golden evals/golden/v1_draft.jsonl --golden-version v1_draft

Interview questions

Q Why not cron?
A You can use cron: go run . --score nightly. The flag is for boxes without cron and for a single-command demo. Both call the same function.
Q What happens if Ollama is down at 3am?
A That tick logs 'scheduled eval failed' and the loop sleeps until the next one. No crash, no silent skip.
Q What would you add for production?
A A lease so two replicas don't run the same tick, metrics for last-success time, and an alert if no run succeeded in 2× the interval.

Remember

  • Same scoreOnce as --score.
  • Failure logs loudly, loop survives.
  • Golden file re-read each tick.
