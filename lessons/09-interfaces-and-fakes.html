Interfaces and fakes: how the tests stay fast

In one sentence

The router depends on a one-method Generator interface, so tests swap in a fake instead of a real model.

Why it exists

A test that needs Ollama running is not a unit test. Small interfaces at the boundary let every package test run in milliseconds, offline, deterministically.

How it works in this project

// router/server.go — the boundary
type Generator interface {
    Generate(model, prompt string, maxTokens int) (string, int, error)
}

// router/router_test.go — the fake
type fakeGen struct {
    text string; tokens int; err error
    model string; lastMaxTokens int      // records what it was called with
}
func (f *fakeGen) Generate(model, prompt string, maxTokens int) (string, int, error) {
    f.lastMaxTokens = maxTokens; f.model = model
    return f.text, f.tokens, f.err
}

// a test
srv := NewServer("fast-m", "quality-m", &fakeGen{err: errors.New("down")})
// ... POST → expect 502 + error.trace_id != ""

The same trick everywhere: tracker/tracker.go has a Store interface with SQLStore (real) and MemStore (test); evals/judge.go has a Judge interface. main.go wires the real ones.

Try it yourself

Run go test ./router/ -v. Notice it finishes in ~1–2 s with no Ollama and no Postgres running.

Interview questions

Q How do you test code that calls an LLM?
A Put the LLM call behind a one-method interface and inject a fake in tests. The fake returns canned text or an error and records what it was called with.
Q What's the difference between MemStore and SQLStore?
A Same interface. MemStore is maps behind a mutex, for tests. SQLStore issues the real SQL through tiny Execer/Queryer interfaces so it never imports pgx.
Q How do you know a test actually guards something?
A Bind-check: temporarily break the code, run the test, it must fail. I did that for the histogram test and the tracker resume test.

Remember

  • Interfaces at I/O boundaries: Generator, Store, Judge.
  • Fakes record calls and return canned results.
  • Tests run offline in seconds.
