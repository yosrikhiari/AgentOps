# ADR-0009 — Generation parameters, client references and extra local models (v1.1)

**Status:** accepted (2026-09-18) · **Context:** the first real multi-agent client. Versatile's writing pipeline was rebuilt as a LangGraph graph with one model per role — Writer on the GPU (`qwen3:8b`), Critic and Editor on a CPU model (`qwen2.5:3b-instruct`, `num_gpu: 0`) so the GPU model is never evicted, a seeded low-temperature judge, JSON-schema output for the critic and the editor, and `keep_alive` so a CPU model stays resident between supersteps. Pointed at the v1.0 gateway it failed on the first call: `unknown_model` for the 3B model, and every parameter but `max_tokens` silently dropped — the judge would have run at the model's default temperature and the graph would have had no way to find the gateway trace for a given decision.

**Decision.**

1. **`GenParams` and `ParamBackend`.** The request gains the OpenAI-shaped `temperature`, `top_p`, `seed`, `stop`, `response_format` and the Ollama-shaped `format`, `options`, `keep_alive`; `paramsOf(req)` lifts them into one `GenParams` value. A backend that can honour them implements `ParamBackend` (`GenerateWith` / `StreamWith`); the server type-asserts and falls back to `Generate` / `Stream` with `max_tokens` alone. The v1.0 `Backend` interface is untouched, so fakes and any third backend keep compiling. Ollama merges the named parameters into `options` (named wins over the passthrough map) and sends `format` / `keep_alive` top-level; the OpenAI backend forwards what an OpenAI-style API understands and drops the Ollama-only knobs rather than sending them to a hosted API.
2. **Values on spans, never content.** `model.generate` records `params` (temperature, seed, num_gpu, num_ctx, keep_alive, `format: "json" | "json_schema"`…) and `params_forwarded`. A JSON schema is content-shaped — it names the fields a prompt asks for — so only its kind is recorded. `TestParamsOnSpan` posts a prompt and a schema with a marker word and asserts neither reaches any span; the existing prompts-never-in-spans policy keeps the rule.
3. **`X-Client-Ref` / `X-Agent-Role`.** Opaque strings (also accepted as body fields), truncated at 64 / 32 chars, attached to all three spans of the trace and echoed as response headers. The client stores the gateway's `X-Trace-ID` next to its own record; the trace inspector can group by `agent_role`. Truncation, not rejection: a client bug must not turn into a span that carries a prompt.
4. **`OLLAMA_MODELS`.** Extra local models registered with tier `local`; explicit by name, local for the fail-closed rule, listed by `GET /v1/models`. Auto-routing still only chooses between the two tier models.

**Alternatives rejected.** *Change the `Backend` interface* — breaks every implementation for a feature a plain backend can legitimately not support. *Forward the whole body opaquely* — the gateway would stop knowing what it sent, which is the point of the gateway. *Record the schema on the span* — content by another name.

**Consequences.** A multi-agent client gets per-role placement and deterministic judging through the gateway with a joinable trace per call, at the cost of one more interface and eight optional request fields. What remains outside the gateway: tool calling, `/v1/embeddings`, and a second cloud model — each is its own decision when a client needs it.
