# Changelog

All notable changes. Dates are 2026.

## Unreleased

- **The judge is now measured, not assumed (`--judge-audit`):** a hand-labelled set of 20 claim/context pairs (`evals/golden/judge-audit.jsonl`, each item naming its source document) is judged with retrieval out of the loop, so a failed lookup cannot be mistaken for a failed judgement. The report gives the confusion matrix with **"unsupported" as the positive class** — `fn` is a hallucination the judge waved through, `fp` is the false alarm that made a faithful paraphrase score 0.00 during the November probe — plus precision, recall, false-alarm rate, Cohen's κ when a second judge is configured, and a flip probe that re-judges every item with the context lines reversed. A judge call that errors is counted, never folded in as agreement; when no verdicts are produced the command exits 2 rather than printing a table of zeros. Live on this box: `phi4-mini:3.8b` scored 11 TP / 0 FN / 0 FP / 9 TN, 0 flips in 12 comparable items, over 20 items — a ceiling-effect result on an easy seed set, which is why the threshold (recall ≥ 0.80, false alarm ≤ 0.20) is a floor, not a claim.

- **An unknown API path now answers in the JSON error envelope, and a silent local outage says so once:** `GET /v1/nope` (or the `/v1/chat/completion` typo) used to fall through to `net/http`'s plain-text `404 page not found` — the only response in the gateway that was not `{"error":{"code",…}}` — so an agent parsing every response as JSON got a parse error instead of a code. Unmatched paths now return `404 not_found`, and a known path with the wrong verb returns `405 method_not_allowed` with `Allow` (which net/http also answered in plain text). Separately, the health prober now logs a local backend's first observed state and every transition: a box where Ollama is unreachable from boot used to fail over to the cloud silently, one log line per request, with no line saying local was never in play.

- **Heat is recorded as a consequence, not only a reading (`0012_gpu_thermal.sql`):** the prober now reads `clocks_event_reasons.active` from `nvidia-smi` and stores `throttled` on every `gpu_samples` row when the driver has cut clocks for heat (bits `0x20` SW / `0x40` HW thermal slowdown). The column is nullable on purpose: `true`/`false` are measured, `NULL` means the driver does not answer the question (a six-column `nvidia-smi`, or an unparsable mask) — "unasked" is never written as "cool". `/metrics` gains the eighth `gpu_*` series, `gpu_thermal_throttled`, which is absent rather than 0 when the driver cannot be asked; `GET /v1/gpu` carries `throttled` per sample; a window's `gpu.Summary` gains `max_temp_c` (omitted when the driver reports no temperature) and `throttled_samples`, so `--score`, `--release-gate`, the `#/evals` runs table (a `throttled 4/41` chip) and `#/gpu` (an amber `throttled` pill plus an explanation) all say when the clock was cut under the work. Why it matters: heat never changes what a model computes — the sampling temperature does that, and the judge is pinned to 0 — but it changes how long it takes, which is exactly what latency comparisons and timeout budgets rest on. This box's driver reports 42 minutes of accumulated SW thermal slowdown since load, so "a slow run" needed to stop being ambiguous.

- **An unjudged eval run is no longer reported as 0.000:** a run whose pairs were all retrieval misses (empty corpus) used to store `score = 0`, so drift and the release gate treated "nothing was judged" as "everything was hallucinated" and the evals page painted a red 0.000. Drift and the gate now require at least one pair with a faithfulness value, `GET /v1/evals/runs` returns `judged`, the runs table shows an `unmeasured` chip when it is zero, and `--score` prints a warning pointing at `--ingest`. The run and its miss rows are still recorded — they are evidence about retrieval, just not a faithfulness measurement.

- **Route instrumentation (Phase 0 of intent-aware routing):** every routed request is now labelled before the decision — a closed intent (`extract`, `summarise`, `classify`, `code`, `math`, `reason`, `write`, `chat`), a bounded confidence, and a separate difficulty scalar (length, complexity keywords, required output structure, bundled questions) — and the decision is recorded in `route_decisions` (`0011`) as labels and model names only: trace, intent, confidence, difficulty, policy, tier, reason, chosen, candidate chain, sensitive. The labels also ride on the `route.decide` span. Routing behaviour is unchanged by construction: the policy is still `heuristic-v0`. `--route-replay [--route-window 720h]` prints the mix by intent and tier plus the always-fast/always-quality baselines, and says plainly that AIQ/PGR need Phase 1 shadow outcomes rather than inventing a quality number. The writer mirrors the span sink (buffered queue, drop-and-count) so a dead database costs a request nothing.

- **Cockpit is a conversation now:** one scrollable transcript replaces the truncated 140-character mono lines and the separate "Answer" panel - user turns sit right-aligned on the raised surface, assistant turns sit left with model/backend/reason/token/trace metadata underneath and an amber border on the latest. The composer is an auto-growing textarea (Enter sends, Shift+Enter newlines, disabled while a send is in flight) with the token estimate beside the buttons, a "thinking" row while the model loads, and a failed send that returns your text to the composer for retry instead of duplicating it. Empty state offers three real prompts; the panel head names the active thread; the rail is narrower and keeps the pinned-trace behaviour. Design-system section and example updated in the same change; all colours are tokens and every new class is defined in `tower.css`.

- **Every eval run now records its window, and gets its GPU story (`0010_eval_run_window.sql`):** `eval_runs` gains `started_at` (backfilled to `created_at` for old rows, written by `RecordRun`), `evals.GateRun` carries `started_at`/`created_at`, `--release-gate` prints one GPU line per run in the window (mean/peak utilisation, peak/installed VRAM, swaps; "no samples (prober off)" when the prober was not running), and `GET /v1/evals/runs` enriches each run with `gpu` from a lateral aggregate over its own window - so the `#/evals` runs table shows `GPU 41%` and `3 swaps` chips, or `-` when nothing was measured. This closes the promise the swap counter made: a green window where the judge and the model fought over the card is now visible instead of implied.

- **GPU swap counter, persisted (`0009_gpu_swaps.sql`):** the prober's monotonic model-swap counter now rides on every `gpu_samples` row as `swaps_total`, and `gpu.SQLStore.Summary(from, to)` aggregates a window in one query (sample count, mean/peak utilisation, peak and installed VRAM, swaps as `max-min`). `--score` prints the window it just measured - "gpu during this run: 41 samples, mean 63% util, peak 2.3 of 4.0 GB VRAM, 3 model swap(s) - a swap unloads one model to load another, so this run is not directly comparable with a quiet one" - and says "no samples - the prober was not running" rather than implying a quiet card. `gpu_swap_events_total` is now a true monotonic counter (it was labelled `_total` while reporting the last ten minutes); the rolling window stays on `GET /v1/gpu` as `swaps_last_10m`. Rows written before this migration read 0, which is "nobody counted", not "no swaps".

- **MCP 2026-07-28, dual-era:** the MCP server now speaks the stateless revision (per-request version in `params._meta` or the `MCP-Protocol-Version` header, mandatory `server/discover` returning `supportedVersions`/`capabilities`/`serverInfo`, JSON-RPC `-32022` with the supported list for an unknown version) while keeping the legacy `initialize` handshake back to `2024-11-05` - old and new clients both work, and `initialize` now echoes the version the client asked for. The Tasks extension is deliberately not implemented (the five tools are fast reads) and the `Mcp-Method`/`Mcp-Name` headers are ignored in favour of the JSON body.

- **Anthropic Messages API ingress:** `POST /v1/messages` accepts the Anthropic request shape (`model`, `max_tokens`, `system`, `messages`, `stream`, `temperature`/`top_p`/`stop_sequences`) with either `x-api-key` or `Authorization: Bearer`, translates it into the same internal `ChatRequest` the OpenAI endpoint uses, and answers in the Anthropic shape - including the `message_start`/`content_block_delta`/`message_stop` streaming events and the Anthropic error envelope. Keys, RPM, token budgets, fail-closed sensitive routing, fallback and spans are therefore identical on both wire formats. `tools`/`tool_choice` and non-text content blocks are rejected with `400 invalid_request_error` rather than silently dropped, because an agentic client that gets an answer without its `tool_use` block hangs; tool passthrough is the next task. Ollama and LM Studio both serve this API now, so local clients written against it can point at this gateway unchanged.

- **Release trust pack - verifiable binaries:** a tagged build now ships linux/darwin/windows on amd64 and arm64 with `-trimpath`, an SPDX SBOM, a Sigstore keyless signature over `SHA256SUMS` (`SHA256SUMS.sigstore.json`), and a GitHub build-provenance attestation; `--version` prints version, commit and build date and `--version-json` prints the same as one JSON line (falling back to the VCS stamps Go embeds for a plain `go build`); README gains a four-command "verify a release" block. Motivated by the two 2026 LiteLLM supply-chain compromises (1.82.7/1.82.8 in March, 1.107.0 in October). The signing step is only provable at the first tag - GitHub's OIDC issuer is not available locally - so the workflow is the deliverable, not a local test.

## v1.0.0 — 2026-09-15

The MVP becomes a product: an installable gateway with a console.

### Track A — ops foundation
- `Dockerfile` (multi-stage, distroless nonroot, 21.7 MB) and a compose `app` profile that runs the router against the host's Ollama.
- GitHub Actions: gofmt · vet · `test -race` · build · docker build on every push; release job on `v*` tags builds linux/windows/darwin binaries + `SHA256SUMS`.
- `schema_migrations` tracking: `--migrate` applies each `migrations/*.sql` once and reports the count.
- Dependabot for Go modules, Docker base images and Actions. `--version` flag stamped at release.

### Track B — gateway hardening
- **OpenAI-compatible** `POST /v1/chat/completions`: `messages[]` in, `chat.completion` out, with `text/reason/backend/trace_id/fallback` extensions. The MVP `{prompt}` body still works.
- **Streaming** (`stream: true`) as SSE in the OpenAI chunk shape; usage in the final chunk.
- **Backends**: `Backend` interface; Ollama moved to `/api/chat` with NDJSON streaming; `OpenAIBackend` for Groq or any OpenAI-style API; 15 s health prober → `router_backend_up{backend}`; `GET /v1/models`.
- **Virtual API keys** (`0003_api_keys.sql`, `--create-key NAME --key-rpm N --key-budget T`): Bearer auth, per-key requests-per-minute, lifetime token budget, 401/403/429 in the one error shape, per-key counters.
- **Fail-closed rule**: sensitive requests (header, body flag, keyword) never get a cloud candidate; explicit cloud model → `403 sensitive_cloud_blocked`.
- Graceful shutdown (drain in-flight chats, flush spans), `REQUEST_TIMEOUT` → 504, `X-Trace-ID` on every response, `X-Request-ID` echo.

### Track C — Tower console
- Web UI served from the binary at `/` (embedded HTML/CSS/JS, no framework, no build step): overview (KPIs, routing traffic, backend health, recent requests), trace inspector, evals & drift (score history, worst cases, *Run eval suite*), workflows (start/resume).
- Console endpoints: `/v1/overview`, `/v1/requests`, `/v1/evals/{runs,status,run}`, `/v1/workflows` (+ `/{id}/resume`).
- Hardening: abortable fetches, one retry on 5xx, inline error + Retry on store failure, in-place polling.

### Fixes and learnings recorded along the way
- Prometheus histogram was double-cumulated (p99 would have been wrong). Fixed + test.
- Recall could exceed 1 when a doc's two chunks were both retrieved. Fixed + test.
- Local judge sampled at default temperature; pinned to 0. Fixed + test.
- Golden answers must be standalone main-clause sentences (one-word, list, and "Because…" answers score 0). `--freeze-golden` now rejects them.
- Eval run budget is `EVAL_TIMEOUT` (default 90 min); evals and live traffic contend for the 8 GB GPU (`docs/VRAM.md`).
