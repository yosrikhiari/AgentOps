Drift detection: did the score drop?

In one sentence

Every eval run is stored; the drift report compares the last two runs for a golden version and alerts when the latest score is below the threshold.

Why it exists

A model, a prompt, a corpus edit or an Ollama upgrade can quietly make answers worse. Drift detection turns 'I think it got worse' into a number, a delta, and the three worst questions.

How it works in this project

-- one row per run + one row per question (0002_drift.sql, ADR-0005)
eval_runs(id, golden_version, judge_model, score, created_at)
eval_pair_scores(run_id, question, faithfulness, precision, recall)

// evals/drift.go
SELECT ... FROM eval_runs WHERE golden_version=$1 ORDER BY created_at DESC LIMIT 2
rep.ScoreNow, rep.ScoreThen = runs[0].score, runs[1].score
rep.Delta        = ScoreNow - ScoreThen
rep.Alert        = ScoreNow < threshold            // EVAL_THRESHOLD, default 0.7
rep.JudgeChanged = runs[0].judge != runs[1].judge  // don't blame the corpus for a judge swap
SELECT question, faithfulness ... WHERE run_id=$1 ORDER BY faithfulness ASC LIMIT 3   // worst cases

Live proof: run 1 on good answers → faith=1.000 alert=false; run 2 with corrupted answers → faith=0.000 alert=true delta=-1.000, report lists 3 worst cases. The run header and pair rows are written in one transaction (deep-review fix #6) so a crash can't leave a header without scores.

Try it yourself

go run . --drift --drift-golden v1_draft
curl localhost:8080/v1/drift/report
# {"golden_version":"v1_draft","score_then":1,"score_now":0,"delta":-1,"alert":true,"worst_cases":[...]}

Interview questions

Q How do you detect regression in an AI system?
A Store every eval score with its golden version and judge. Compare the latest to the previous, alert below a threshold, and surface the worst questions so you can look at them.
Q Why store per-question scores, not just the average?
A Because the average hides which question broke. Per-question rows let the report name the worst cases without re-running 32 judge calls.
Q Why the judge_changed flag?
A If run 1 used Qwen and run 2 used Llama, the delta measures the judges, not the system. The flag stops a false alarm.

Remember

  • Store every run; compare last two.
  • alert = latest < threshold; report delta + worst 3.
  • Header + pair rows in one transaction.
