Part 4 · The fact-checker (RAG + evals)

RAG in plain words

In one sentence

RAG = find the relevant text first, then let the model answer using only that text. Retrieval-Augmented Generation.

Why it exists

Models make things up. If you hand the model the exact paragraphs that contain the answer, it can quote instead of guess — and you can check its answer against those paragraphs. That check is the fact-checker.

How it works in this project

The pipeline in this repo, file by file:

corpus/*.md                 15 short docs you wrote (source of truth)
      │  scripts/clean_docs.py    normalize → chunk (900 chars, 120 overlap) → dedup by hash
      ▼
evals/corpus/clean/*.jsonl  one row per chunk {doc_id, hash, text, source}
      │  go run . --ingest        embed each chunk with nomic-embed-text (768 numbers)
      ▼
Postgres table chunks       text + embedding vector(768) + HNSW index
      │  go run . --search "q"    embed the question, cosine-nearest 5 chunks
      ▼
top-k chunks  ───────────►  the model / the judge reads only these

Two models, two jobs: the embedding model turns text into vectors (tiny, always loaded); the chat model writes answers (big, swapped).

Try it yourself

python scripts/clean_docs.py
go run . --migrate && go run . --ingest
go run . --search "what does the router do?"

Interview questions

Q What is an embedding?
A A list of numbers (here 768) that represents the meaning of a text. Texts with similar meaning get vectors that point in similar directions, so 'nearest vector' ≈ 'most related text'.
Q Why chunk the documents?
A Embeddings work on short passages; a whole document blurs many topics into one vector. 900-character chunks with 120 overlap keep one idea per chunk and avoid cutting a sentence at the boundary.
Q Why is the corpus so small?
A 15 docs is enough to prove the loop and small enough to hand-review every golden answer. Big PDFs would need different chunking and hours of review.

Remember

  • Retrieve first, then generate.
  • Corpus → chunks → embeddings → nearest-k.
  • Embedding model ≠ chat model.
