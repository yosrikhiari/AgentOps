The Tower console: a UI with no framework and no build

In one sentence

Three static files embedded in the binary — HTML, CSS on the Tower design tokens, and a small JS hash router — read a handful of JSON endpoints and show overview, traces, evals and workflows.

Why it exists

The MVP's 'dashboard' was JSON endpoints plus Grafana. An operator wants to see routing, health, the eval score and a trace on one screen, and click 'run eval' or 'resume workflow'. Doing it without a framework keeps the whole product one binary with zero JS toolchain.

How it works in this project

console/
  handler.go      GET /  (embed.FS)  + /v1/overview /v1/requests /v1/evals/* /v1/workflows*
  store.go        SQL over the same tiny Queryer interface; RecentRequests groups spans per trace
  static/         index.html · tower.css (mockup tokens) · app.js (~350 lines)

// app.js — every page owns an AbortController; 5xx get one retry; 502 → inline error + Retry
async function api(path, opts, signal) { … }

Rules the UI follows: navigating away cancels the previous page's fetches; store failures render an error box with a Retry button instead of a blank page; polling refreshes data panels in place and never replaces a field the user is typing in (the first version re-rendered the whole page every 4 s and ate a click — caught in the browser check).

The overview is derived from spans, not from a separate metrics table: model.generate spans of the last hour give requests, p50/p99, tokens and errors; route.decide gives tier, reason and the sensitive flag. One source of truth.

Try it yourself

Run go run . and open http://localhost:8080. Stop Postgres (docker stop agentops-postgres): the page shows an error with Retry, while curl …/v1/chat/completions still answers — telemetry is off the request path. Start Postgres, click Retry.

Interview questions

Q Why no React?
A The console is four pages of tables and two SVG charts. A ~350-line vanilla script covers it with no build step, so the product stays one go build. The design tokens came straight from the mockup's CSS.
Q How does the UI get its data?
A From spans. Recent requests join a trace's route.decide and model.generate spans; the KPI header aggregates the last hour of them. No second bookkeeping table to keep in sync.
Q What broke in the browser check?
A Clicking 'Start workflow' did nothing — the page re-rendered itself every 4 s while a workflow was running, replacing the button under the cursor and wiping the input. Fixed by building forms once and refreshing only the data panels.

Remember

  • Embedded static files; no framework, no build step.
  • Overview derived from spans — one source of truth.
  • AbortController per page, retry on 5xx, never yank a focused input.
