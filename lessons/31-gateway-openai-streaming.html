From router to gateway: OpenAI shape, streaming, backends

In one sentence

v1.0 made the router something a real client can point at: OpenAI-compatible messages[] in and out, SSE streaming, and pluggable backends (Ollama + any OpenAI-style cloud API) behind one Backend interface.

Why it exists

Every LLM client library speaks the OpenAI chat shape. If the gateway speaks it too, swapping AgentOps in front of an app is a base-URL change. Streaming matters because a 7B model on a laptop takes seconds — users need to see tokens arrive.

How it works in this project

// router/backend.go — one interface, three implementations (Ollama, OpenAI-style, test fake)
type Backend interface {
    Name() string
    Generate(ctx, model string, msgs []Message, maxTokens int) (string, Usage, error)
    Stream(ctx, model string, msgs []Message, maxTokens int, emit func(delta string)) (Usage, error)
    Health(ctx) error
}
type Local interface{ Local() bool }   // sensitive data may only use backends that say true

// router/server.go — the same handler serves both shapes
{"prompt":"hi"}                                     // MVP body, still accepted
{"model":"auto","messages":[{"role":"user","content":"hi"}],"stream":true}   // OpenAI body

Ollama streams newline-delimited JSON with the token counts on the final done:true line; OpenAI-style APIs stream data: SSE lines ending in [DONE], with usage either in the last chunk (stream_options.include_usage) or in Groq's x_groq block. Both are parsed in ~40 lines each and tested against real protocol bytes with httptest.

The response is an OpenAI chat.completion plus AgentOps extensions (reason, backend, trace_id, fallback). OpenAI clients ignore the extras; the MVP's clients keep reading text. Streaming counts metrics once, at the end, with the streamed usage.

Try it yourself

curl -N localhost:8080/v1/chat/completions -d '{"messages":[{"role":"user","content":"count to 5"}],"stream":true}'
# data: {"choices":[{"delta":{"content":"1"},…}]}   … data: [DONE]

Interview questions

Q Why one Backend interface?
A So routing, metrics, spans and the fail-closed rule are written once against Generate/Stream/Health, and a new provider is one file. The test fake implements the same interface, so the whole gateway is unit-tested offline.
Q How do you handle an error in the middle of a stream?
A Before the first delta, it is a normal HTTP error and the router can try the next candidate. After the first delta the status is already 200, so the failure becomes a data: {"error":…} event followed by [DONE].
Q What does 'health' buy you?
A A 15-second prober sets router_backend_up{backend}, feeds GET /v1/models and the console, and lets the router skip a fallback it already knows is down instead of paying a timeout.

Remember

  • One Backend interface: Generate / Stream / Health.
  • OpenAI shape in and out; MVP body still works.
  • Streaming: errors before the first delta are HTTP errors, after it they are events.
